# B1.3 — L4 Catalog (DataHub + OpenSearch) — Design

**Slice:** B1 Data mesh → B1.3 (L4 Catalog / Contracts)
**Status:** Design approved 2026-06-25
**Depends on:** B1.1 (Keycloak SSO), B1.2 (data-mesh ns, Postgres, MinIO, Istio mesh)

## Goal

Stand up **DataHub** as the always-on metadata catalog, on a **shared OpenSearch** search/graph tier, slimmed for a single k3s node. This is the L4 centerpiece the rest of the mesh (lineage, contracts, discovery) hangs off.

## Locked decisions (with rationale)

| # | Decision | Rationale |
|---|----------|-----------|
| 1 | **Footprint = slim single-node** | Drop everything the single node doesn't need; keep a fully functional catalog. |
| 2 | **Two decoupled search instances** (revised 2026-06-25): (a) an **exposed OpenSearch 3.x playground**; (b) DataHub's **own bundled OpenSearch 2.19.5** (the `datahub-prerequisites` chart's default, Apache-2.0). | DataHub only supports OpenSearch **2.x** (`OPENSEARCH_2` shim; 3.x is "planned, not available" — [docs](https://docs.datahub.com/docs/how/elasticsearch-search-client-shim)). Sharing one instance would peg the playground to a legacy engine. So decouple: the exposed surface runs **latest** (3.x); DataHub's engine is an invisible internal dependency on the chart's paved path. The prereq chart bundles **OpenSearch 2.19.5** (not Elasticsearch) — so it's Apache-licensed and the same engine family as the playground; the chart auto-wires it + Kafka, co-tested, upgrades ride the chart. |
| 3 | **DataHub's bundled search serves search *and* graph** — no Neo4j | DataHub's ES-graph is fully supported; reusing the existing community Neo4j would entangle DataHub's metadata graph with the GraphRAG/B37 graph in one DB/blast-radius for zero RAM saving. |
| 4 | **OpenSearch Dashboards (3.x) included now** on the exposed playground | It *realizes* the "first-class shared search surface" rationale — browse indices, run search/log experiments. Forward-auth gated. Tied to the playground (3.x), not DataHub's engine. |
| 5 | **Kafka = own single-broker KRaft**, no Zookeeper, DataHub-internal | DataHub needs an always-on bus (`MetadataChangeLog`/`MetadataChangeProposal`). Distinct from the B1.5 on-demand Strimzi data-Kafka — kept separate so the experimental streaming tier stays isolated/teardownable and B1.5 still gets to learn Strimzi. |
| 6 | **Schema Registry = INTERNAL** (GMS built-in) | DataHub is the only Kafka tenant today; the one future tenant (B1.5 streaming) is on-demand and should own its own registry. No standalone Confluent SR. |
| 7 | **MAE/MCE consumers embedded in GMS** | Two fewer pods, identical function; standalone consumers only pay off when scaling ingestion independently of GMS — a single node won't. Splittable later via one flag. |
| 8 | **Relational store = reuse existing Postgres**, new `datahub` DB | Lab pattern (Nessie/lakeFS/MLflow/Keycloak). No bundled MySQL. |
| 9 | **DataHub frontend = native OIDC** to Keycloak | A catalog tracks ownership/audit/authz; native OIDC gives real per-user identity that DataHub policies bind to (sets up B1.6 governance). Forward-auth would collapse all users to one. |
| 10 | **Deploy = official DataHub Helm charts via Argo** | Matches every heavy app (loki/tempo/kube-prometheus/opencost/woodpecker/keda): multi-source App, chart pinned + `$values` from git, observe-only, SSA=true. Slim via values. |
| 11 | **Namespaces:** exposed OpenSearch 3.x playground → own `opensearch` ns; DataHub + its bundled search → existing `data-mesh` ns | The playground is *shared infra* (own ns, like `monitoring`); DataHub *is* the L4 mesh layer (lives with Nessie/lakeFS), and its bundled search is a DataHub-internal component. |

## Architecture

### `opensearch` ns — exposed search playground (standalone, latest)

- **OpenSearch 3.x** (latest, Apache-2.0) — single-node Helm chart via Argo. 1 replica, **JVM heap 1 GB** (`-Xms1g -Xmx1g`), ~20 GB local-path PVC, **security plugin disabled** (LAN-internal, plain HTTP on :9200). **Not used by DataHub** — this is the modern search/log surface for experiments.
- **OpenSearch Dashboards 3.x** — the search UI. Ingress `opensearch.weyland.lab`, **forward-auth** gated via a **local `traefik-forward-auth` Middleware in this ns** (Dashboards has no auth of its own with the security plugin off; cross-ns middleware is blocked).
- **Un-meshed** — nothing in the mesh depends on it; it never touches Postgres. (Can join PERMISSIVE later for observability if wanted.)

### `data-mesh` ns — DataHub + its bundled search (alongside Nessie/lakeFS)

- **Bundled search** — DataHub's **own OpenSearch 2.19.5** via the `datahub-prerequisites` chart (`opensearch.enabled: true`, the chart default; `elasticsearch` stays off), **heap 1 GB**, single-node, security plugin off, in-cluster only, no Dashboards/ingress. Engine type `OPENSEARCH_2`. DataHub-internal dependency — the chart auto-wires it to GMS.
- **GMS** (Generalized Metadata Service) — core backend. **Meshed** (sidecar inject) because it talks to STRICT-mTLS Postgres. MAE/MCE consumers embedded (`MAE_CONSUMER_ENABLED`/`MCE_CONSUMER_ENABLED=true`). Internal schema registry. `graph_service_impl=elasticsearch` → the **bundled** search (search + graph). No Neo4j.
- **Frontend** (`datahub-frontend`) — React UI. Ingress `datahub.weyland.lab`, **native OIDC** (`AUTH_OIDC_ENABLED=true` + client id/secret/discovery). Requires a new `keycloak_openid_client` in `tofu/keycloak`, an OIDC client-secret k8s Secret, and the **mkcert root imported into the JVM truststore** for the Keycloak back-channel (JVM version of the B1.1 CA-bundle gotcha).
- **Kafka** — single-broker **KRaft** (no Zookeeper) via the same `datahub-prerequisites` chart with `neo4j`/`mysql`/`cp-schema-registry` disabled → the prereq chart provides **Kafka + the bundled Elasticsearch** (only those two).
- **Postgres** — reuse the existing meshed Postgres; create the **`datahub` DB** (via `kubectl exec` into the postgres pod, superuser from `POSTGRES_USER`).
- **Setup jobs** (run-once k8s Jobs, then idle): `elasticsearch-setup` (indices/templates), `kafka-setup` (topics), `postgres-setup` (schema), `system-update` (migrations / restore-indices).

## Data flow

1. Ingestion source (later: Dagster/OpenLineage, Trino, dbt) → MCE → Kafka `MetadataChangeProposal`.
2. GMS (embedded MCE consumer) → writes metadata to **Postgres** (source of truth) + emits `MetadataChangeLog`.
3. GMS (embedded MAE consumer) → updates the **bundled Elasticsearch** search + graph indices.
4. Frontend → GMS REST/GraphQL → reads from Postgres + the bundled search; user identity via Keycloak OIDC.

(The `opensearch` ns 3.x playground is entirely separate from this flow — DataHub never touches it.)

## Footprint & pre-flight gate

Steady-state estimate (two search instances now): playground OpenSearch 3.x ~2 GB + Dashboards ~0.5 GB + DataHub bundled OpenSearch 2.19.5 ~2 GB + Kafka ~1 GB + GMS ~1.5–2 GB + frontend ~0.5 GB ≈ **~8 GB** on the mother k3s VM. **Both search heaps held at 1 GB** to keep this in budget.

**Step 0 — headroom gate** (precedent: B8 step-0): check free RAM on mother *before* deploy. **Verified 2026-06-25: 14 GB available, node 56%** → proceed full, both heaps 1 GB (lands node ~84%). If a future re-run shows much less, stage the playground first, DataHub second, re-check between.

## Hostnames

New (need `/etc/hosts` on the workstation + CoreDNS already wildcards `*.weyland.lab` → Traefik):
- `datahub.weyland.lab` — DataHub frontend (OIDC)
- `opensearch.weyland.lab` — OpenSearch Dashboards (forward-auth)

In-cluster only (no ingress): GMS, Kafka, OpenSearch :9200.

## Files (anticipated)

- `k8s/opensearch/` — Argo values for OpenSearch + Dashboards + the local forward-auth Middleware + Dashboards Ingress.
- `k8s/data-mesh/datahub-values.yaml` (+ prereq values) — DataHub Helm values; GMS/frontend/setup-jobs config; frontend OIDC env + Ingress.
- `k8s/argocd/applications/helm-apps.yaml` — add `opensearch`, `datahub-prerequisites`, `datahub` Argo Applications.
- `tofu/keycloak/datahub.tf` — `keycloak_openid_client` for the frontend.
- Secrets (`*.example.yaml` + real, git-ignored): OIDC client secret; any OpenSearch creds if security is ever enabled.

## Out of scope (later slices)

- **ODCS data contracts** — DataHub native data products + contracts/assertions (B1.3 follow-on, after the catalog is live).
- **OpenLineage → DataHub** ingestion from Dagster (B1.6; drops Marquez).
- **Trino / dbt** source ingestion (B1.4 / B1.5).
- OpenSearch security plugin / per-user auth on the search tier (deferred; LAN-internal + forward-auth on Dashboards covers it for now).

## Open risks

- **Node RAM** — the headroom gate addresses it; heap is the main flex.
- **DataHub ↔ search version compat** — RESOLVED by the 2026-06-25 pivot: DataHub uses its **bundled OpenSearch 2.19.5** (`OPENSEARCH_2`, fully supported), so it's not coupled to the playground's version. The playground runs OpenSearch 3.x independently. (DataHub does *not* yet support OpenSearch 3.x — [shim docs](https://docs.datahub.com/docs/how/elasticsearch-search-client-shim).)
- **JVM truststore for OIDC back-channel** — the frontend (Play/JVM) reaching `keycloak.weyland.lab` (mkcert) needs the mkcert root in a Java truststore, not `REQUESTS_CA_BUNDLE`. New variant of a known gotcha.
- **`datahub-prerequisites` KRaft support** — confirm the pinned prereq chart version defaults/permits single-broker KRaft (recent bitnami Kafka does); else pin Kafka subchart accordingly.
