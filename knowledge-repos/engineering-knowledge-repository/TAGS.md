# Master Tag List

All entries in the Engineering Knowledge Repository must be tagged using values from this list. Tags are applied across three axes: **domain**, **type**, and **scope**. An entry can have multiple tags from each axis.

When contributing a new entry, check here first. Do not invent new tags — propose additions to this list instead.

---

## Domain Tags
What area of engineering the entry belongs to.

| Tag | Definition |
|---|---|
| `ai-ml` | Machine learning systems, model serving, AI pipelines, and LLM integration patterns |
| `api-design` | API contracts, protocols, patterns, and conventions |
| `concurrency` | Parallel execution, thread safety, async coordination |
| `cost` | Cloud spend, resource efficiency, FinOps |
| `data` | Data modeling, storage, querying, pipelines |
| `deployment` | Releasing and delivering software to environments |
| `developer-experience` | Tooling, workflows, and practices that affect engineering productivity |
| `infrastructure` | Cloud resources, networking, compute, storage |
| `observability` | Monitoring, logging, tracing, alerting, dashboards |
| `performance` | Latency, throughput, resource efficiency at runtime |
| `reliability` | Fault tolerance, availability, recovery, resilience |
| `security` | Auth, authorization, cryptography, threat mitigation |
| `team-practices` | Engineering culture, process, collaboration, and org patterns |
| `testing` | Verification, validation, quality assurance |

---

## Type Tags
What kind of thing the entry describes.

| Tag | Definition |
|---|---|
| `anti-pattern` | A commonly used approach that causes more problems than it solves |
| `methodology` | A structured process or framework for how to work |
| `pattern` | A reusable solution to a recurring design or implementation problem |
| `principle` | A guiding rule or value that shapes decision-making |
| `protocol` | A formal standard for communication or data exchange |
| `reference` | A taxonomy, checklist, or catalog (e.g. OWASP Top Ten, DORA metrics) |
| `tooling` | A specific tool, library, or platform |

---

## Scope Tags
What level of the system the entry operates at.

| Tag | Definition |
|---|---|
| `backend` | Server-side application logic and services |
| `cloud` | Cloud provider services and cloud-native infrastructure |
| `database` | Relational, document, key-value, and other data stores |
| `distributed-systems` | Systems composed of multiple networked components |
| `frontend` | Client-side applications and browser-based systems |
| `microservices` | Independently deployable service architectures |
| `monolith` | Single-deployment application architectures |
| `network` | HTTP, DNS, TLS, load balancing, and transport-layer concerns |
